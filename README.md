# 📈 기능 구현 리스트

### 1. 사용자 입력

- `@woowacourse/mission-utils`에서 제공하는 `Console.readLineAsync` 를 이용해 사용자 입력을 받는다.

- `덧셈할 문자열을 입력해 주세요.` 라는 문구가 나와야한다.

### 2. 입력값 파싱

- 입력한 문자열에서 구분자를 기준으로 숫자를 추출한다.

  - 구분자는 커스텀 구분자와 기본 구분자로 나뉜다.

    - 기본 구분자는 `쉼표(,)와 콜론(:)`을 기본 구분자로 사용하고 커스텀 구분자와 같이 사용이 가능하게 설계
    - ex) `//&\n1&2,3:4`

  - 커스텀 구분자는 `//`와 `\n` 사이에 위치하는 문자를 커스텀 구분자로 사용한다.

### 3. 숫자 계산

- 구분자로 분리된 숫자들을 더한다.

### 4. 결과 출력

- `@woowacourse/mission-utils`에서 제공하는 `Console.print` 를 이용해 계산 결과를 출력한다.

- `결과 : ${result}` 형식의 결과가 출력 되어야한다.

# 🤔 스스로 판단한 예외 처리

- 에러는 `[ERROR]`로 시작하는 에러 메시지를 출력 후 애플리케이션은 종료되어야 한다.
- 별도의 객체 형식의 에러 상수 파일을 만들어 사용
- 단, 구분자는 연속으로 사용 할 수 있게 할 예정임
  - ex) `1,,2` → `[1, 0, 2]`
  - **Why?** : 기능 요구 사항에 `"" → 0`이라고 적혀있다. 구분자는 말 그대로 구분하는 용도이기 때문에 값은 없지만 빈 문자라고 판단해서 0 변환

### 커스텀 구분자 에러

- **커스텀 구분자 형식이 있지만 빈 값일 경우**

  - ex) `//\n1,2`
  - `[ERROR] 커스텀 구분자가 비어 있습니다.`

- **커스텀 구분자의 길이가 1을 초과 할 경우**

  - 이 경우는 기능 요구 사항에 적힌  
    `문자열 앞부분의 "//"와 "\n" 사이에 위치하는 문자를 커스텀 구분자로 사용한다.`  
    에서 `문자를` → 한 글자만 가능으로 판단했다.

  - ex) `//&&\n1&&2`
  - `[ERROR] 커스텀 구분자는 한 문자만 입력할 수 있습니다.`

- **커스텀 구분자에 숫자가 들어간 경우**

  - ex) `//1\n112`
  - `[ERROR] 커스텀 구분자에는 숫자를 사용할 수 없습니다.`

### 사용자 입력 에러

- 음수를 입력할 경우

  - ex) `-1,2`
  - `[ERROR] 음수는 입력할 수 없습니다.`

- 유효하지 않은 문자를 입력할 경우

  - ex) `1, a` or `//&\n1$2`
  - `[ERROR] 구분자와 양수외에 잘못된 문자가 입력되었습니다.`

### 연산 에러

- **Safe Integer 범위를 초과**
- ex) `9007199254740992` 또는 `9007199254740991,2`
- `[ERROR] 연산 결과가 최대 정수 범위를 초과했습니다.`
- `Number.MAX_SAFE_INTEGER (2^53 - 1)`를 초과할 경우 정밀도 손실이 발생

## 🤔 App.js에 방황한 로직들을 어떤 구조로 리팩토링 할까

- 공부가 목표기 때문에 사용 해보지 않았던 MVC 패턴으로 구조 설계
- Model, View, Controller 세가지의 역할로 구분

### Model

- **데이터와 비지니스 로직을 관리**

  - 커스텀 구분자 파싱
  - 커스텀 구분자 검증
  - 구분자를 기준으로 문자열 분리
  - 사용자 입력 검증
  - 덧셈 계산

### View

- **사용자의 UI를 담당**

  - 사용자 입력 받기
  - 결과 출력

### Controller

- **Model, View를 연결하고 전체 흐름 제어**
- App.js에서 컨트롤러를 실행

# 🤦‍♂️ 과제를 수행하며 느낀점

## 1. 클래스와 MVC 패턴 학습 경험

- 내 자신이 많이 부족하다는 느낌을 받았다.  
  과제가 주어지고 4일 동안은 함수로 구현하며 40개 이상의 커밋을 했지만 파일의 양이 점차 많아지고 간단한 로직 구현인데 생각이 많아져 복잡해지는 느낌을 받았다.

  - 결국 이건 공부에 도움이 안될거같아 브랜치를 초기화 시켜 내가 약한 클래스로 구현 해보기로 했다.

  - 클래스를 공부하며 MVC 패턴에 대해 알게 되었고 적용해 보기로 했다.

  - 함수로만 분리하던 로직은 점차 파일의 양이 많아지며 오히려 복잡한 역할 분리 느낌을 주기도 했었는데 MVC 패턴은 `Model`,`View`,`Controller` 세가지의 역할 분리로 전보다는 보기 편해졌다.

## 2. 기능 목록 정리의 중요성

- 과제를 무작정 구현하지 않고 기능 목록 정리를 하고 설계한 내용을 구현하니 무엇을 만들어야 하는지 명확하게 파악할 수 있었고, 특히 구현 순서를 계획하는게 도움이 컸다.

- 예외 처리도 내가 의도된 동작만을 정의하고 개발하다 보니 왜 테크코스에서 기능 목록을 먼저 정리 하라고 했는지 느끼는 1주차였다.

## 3. Git 커밋 컨벤션 학습

- 깃 커밋 컨벤션을 지키면서 커밋을 한건 이번이 처음인데 어떻게 메시지를 작성해야 되는지 배우게 되는 시간이었다.

- 기능 단위로 커밋하다 보니 Commit Type도 명확하게 할 수 있었다.

## 4. Jest 테스팅 경험

- 처음으로 Jest로 테스팅을 해봤는데 테스팅은 단순 검증뿐 아니라 설계 가이드 역할도 하는 것을 느꼈다.

- 테스팅은 아직 부족한 점이 많아 많은 사이트를 참고하여 공부해야겠다.

- describe로 테스트 그룹을 묶고 테스팅의 그룹화도 신경 써야 하는점을 알았다.
